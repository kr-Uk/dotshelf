# DotShelf 학습 시리즈

이 폴더는 **"DotShelf 백엔드가 어떻게 돌아가는지 0에서부터 이해"** 하기 위한 가이드입니다.
다른 docs 문서들이 "무엇을 바꿨나" 라면, 여기는 "이게 원래 뭐고 왜 이렇게 만들어져 있나" 를 설명합니다.

## 누구를 위한 문서인가

- 백엔드가 처음인 사람
- Spring / JPA / JWT 같은 단어를 "들어는 봤지만 정확히 모르는" 사람
- 우리 코드를 열었는데 어디부터 봐야 할지 막막한 사람
- 발표/면접에서 이 프로젝트를 설명해야 하는 사람

**기준**: "아 그 단어 뭐지?" 싶을 때 바로 여기서 답을 찾을 수 있게. 전문 용어는 첫 등장 시 바로 풀어서 설명합니다.

---

## 먼저, DotShelf 가 뭐야?

한 줄: **내 방 같은 가상 공간에 책을 꽂아두고, 읽은 기록을 남기고, 친구랑 공유하는 앱**.

사용자 관점 흐름을 대충 그려보면:

```
1. 구글/카카오 계정으로 로그인
2. 내 "서재(공간)" 가 만들어짐
3. 책을 검색/등록해서 책장에 꽂음
4. 읽으면서 독서 기록(감상, 줄글, 사진) 을 남김
5. 친구를 팔로우 → 피드에서 친구의 기록을 봄
6. 방명록/좋아요/댓글로 소통
```

그래서 우리 코드엔 `user`, `book`, `bookshelf`, `space`, `readingrecord`, `feed`, `follow`, `guestbook`, `notification` 같은 도메인 폴더가 있습니다. 각각 위 플로우의 한 조각.

---

## "백엔드" 가 뭐야?

식당으로 비유:

- **프론트엔드(웹/모바일 앱)** = **홀**. 손님이 보고 만지는 부분. 메뉴판, 테이블.
- **백엔드(우리)** = **주방**. 주문 받으면 실제로 요리해서 내보내는 부분. 재고 관리, 결제 처리, 예약 저장.
- **둘 사이 통신** = **주문서**. "김치볶음밥 1인분 추가" 같은 내용이 오가는 종이. 웹에선 이걸 **HTTP 요청/응답** 이라고 부름.

사용자 관점에선 백엔드가 안 보여요. 하지만 **데이터를 안전하게 저장하고, 로그인 검증하고, 친구 피드를 계산하는 일** 은 전부 백엔드 몫.

## 우리가 만든 전체 구조 (아주 단순화)

```
   📱 사용자 (모바일 앱 / 웹 브라우저)
        │
        │ HTTPS (암호화된 웹 요청)
        ▼
   ☁️ Cloudflare  ← 전 세계 엣지에서 요청 빠르게 받아주는 방패
        │
        │ 
        ▼
   🖥️ 영구 서버 (prod)          ────────────────┐
        - Nginx (프론트 데스크)                   │
        - PostgreSQL (우리의 데이터베이스)         │  
        - Redis (빠른 임시 기억장치)              │  같은 회사 사내망 같은 느낌
                                                 │  (Tailscale 이라는 사설 네트워크)
                                                 │
   🖥️ SSAFY 서버 (app)          ────────────────┘
        - Spring Boot (실제 로직이 돌아가는 자바 앱)
```

### 왜 서버가 두 개?

간단한 비유:

- **영구 서버** = **우리 본사**. 오래 유지할 거. DB 같은 "잃으면 안 되는 것" 을 여기 둠.
- **SSAFY 서버** = **임시로 빌린 창고**. 프로젝트 끝나면 회수됨. 그래서 **언제든 재생성 가능한 것**(앱 코드) 만 여기 둠.

자세한 배경: [`docs/infra/2026-04-22-tailscale-app-db-split.md`](../infra/2026-04-22-tailscale-app-db-split.md)

## 기술 스택을 "한 줄씩" 소개

처음 보면 낯선 단어 파티인데, 각자 하는 일은 딱 정해져 있어요.

| 이름 | 한마디로 | 비유 |
|---|---|---|
| **Java 21** | 우리가 코드를 쓰는 프로그래밍 언어 | "한국어로 작문" 처럼 "자바어로 프로그램 작성" |
| **Spring Boot** | 웹 서버를 쉽게 만들어주는 도구상자 | 집 짓는 데 쓰는 레고 세트 |
| **JPA / Hibernate** | 자바 객체 ↔ DB 를 자동 변환해주는 장치 | 통역사 (자바어 ↔ SQL어) |
| **QueryDSL** | 복잡한 DB 쿼리를 자바 문법으로 쓰게 해주는 도우미 | SQL 초보자가 쓰기 쉬운 문법 변환기 |
| **Flyway** | DB 스키마 변경 이력을 관리하는 도구 | "DB 의 Git" |
| **PostgreSQL** | 실제 데이터를 저장하는 관계형 DB | 거대하고 튼튼한 엑셀 |
| **Redis** | 아주 빠른 임시 저장소 | 책상 위 포스트잇 (DB 는 서랍) |
| **Nginx** | 요청을 받아 올바른 곳에 전달하는 프록시 | 건물 프론트 데스크 |
| **Docker** | 프로그램을 "컨테이너" 단위로 띄우는 기술 | 기능별 컵라면 (따로따로 포장) |
| **GitLab CI/CD** | 코드 푸시하면 자동으로 빌드/배포 | 공장 컨베이어 벨트 |
| **Tailscale** | 서버 끼리만 통하는 비밀 네트워크 | 두 건물 사이 지하 터널 |
| **Cloudflare** | 외부 공격 막고 응답 빠르게 해주는 중개자 | 경호원 + 배달 대리점 |

이 표만 외워도 전체 문서를 읽는 데 70% 지식은 확보.

## 읽기 전 "용어 미니 사전"

챕터 보다 막히면 여기로 돌아오세요.

- **API** — Application Programming Interface. "기계 간 대화 규칙". 예: `GET /api/books/1` 를 보내면 책 1번 정보가 돌아옴
- **HTTP** — 웹에서 쓰는 대화 프로토콜. "메시지를 어떤 형식으로 주고받을지" 정해놓은 규칙
- **HTTPS** — HTTP 인데 내용이 암호화된 것 (S = Secure)
- **URL** — 웹 주소. 예: `https://api.dotshelf.digital/api/health`
- **IP 주소** — 컴퓨터마다 달린 숫자 번호표. 예: `3.38.240.110`
- **포트(port)** — 같은 IP 안에서 어느 프로그램에 갈지 구분하는 번호. 예: `:5432` = PostgreSQL
- **서버** — 늘 켜져서 요청을 받아주는 컴퓨터
- **클라이언트** — 요청을 보내는 쪽 (브라우저/모바일 앱/다른 프로그램)
- **DB / 데이터베이스** — 데이터를 체계적으로 저장하는 프로그램
- **SQL** — DB 에 질문하는 언어. 예: `SELECT * FROM users WHERE id=1;`
- **JSON** — 데이터를 표현하는 형식. `{"name": "민욱", "age": 25}` 같은 모양
- **컨테이너** — 프로그램 하나를 독립 포장해서 실행하는 기술 (Docker 가 대표)
- **배포(deploy)** — 내 코드를 서버에 올려서 실제로 돌아가게 만드는 과정
- **프로덕션(prod)** — 실제 사용자가 쓰는 운영 환경 (≠ 개발/테스트 환경)

모르는 단어 또 나오면 **그 챕터 안에서** 바로 설명되게 할 예정.

## 읽는 팁

1. **한 번에 하나씩** — 챕터 끝까지 읽고 실제 코드 한번 열어보고 다음 챕터로.
2. **"왜?" 에 집중** — 코드가 어떻게 생겼는지보다, 왜 그렇게 생겼는지가 더 중요.
3. **이해 안 가도 괜찮음** — 1주일 뒤 다시 읽으면 다르게 보임. 용어만 익숙해져도 큰 전진.
4. **비유는 완벽하지 않음** — "nginx 는 프론트 데스크" 같은 비유는 감 잡는 용. 세밀한 부분은 다르니까 너무 문자 그대로 받아들이지 말 것.
